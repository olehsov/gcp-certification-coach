# Contributing

Thanks for helping learners prepare for Google Cloud certifications. Read [CLAUDE.md](CLAUDE.md), [docs/PRD.md](docs/PRD.md) and [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) before larger changes; decisions are recorded in [docs/adr/](docs/adr/).

## First steps

After cloning, run `scripts/setup-hooks.sh` once. Never use `--no-verify`.

```bash
scripts/setup-hooks.sh          # enables .githooks (pre-commit, pre-push)
brew install gitleaks           # optional locally; hooks skip it when absent, CI always runs it
```

Optional: create a personal denylist at `~/.config/gcp-cert-coach/denylist.txt` (one term per line: your name, emails, city, employer). It stays outside the repository; the privacy check reports only the file and line of a match, never the term.

## Repository layout

- `plugins/gcp-cert-coach/`: everything users install (manifest, skills, README, LICENSE, icon). Nothing else goes here.
- `docs/`, `evals/`, `scripts/`, `.github/`: outside the plugin folder.
- One folder per skill under `skills/`, named like the skill. Supporting files sit in that skill's `references/`, `assets/` or `scripts/` and are linked from its `SKILL.md`. Skills never read another skill's folder (ADR 0006); the few shared files are copied and kept identical by `scripts/check-consistency.sh`.
- The tracker page is edited only in `templates/tracker.html` (open it in a browser to preview). After every change run `python3 scripts/build-plugin-data.py` (needs PyYAML), which regenerates `skills/init/assets/tracker-template.json` and its byte-identical copy in `skills/rebuild/assets/`; never edit the JSON by hand. The pre-push hook and CI run `scripts/check-consistency.sh`, which fails when the shipped JSON differs from a fresh run. The same duplication rule applies to `references/browser-progress-check.md`, edited in `init` and copied to `progress` (only line 3, the cross-reference, differs).
- The plugin folder holds only Markdown, YAML, JSON and PNG (no HTML, scripts or lockfiles; ADR 0011). `scripts/check-file-types.sh --inventory` shows what libmagic and Magika detect; it runs in the pre-push hook, CI and `build-zip.sh` (`pip install magika==1.0.3`). Do not quote page tags in skill Markdown: content detection reads such a file as HTML.

## Adding a certification pack

1. Create `plugins/gcp-cert-coach/skills/init/assets/packs/<certId>/` with `pack.yaml`, `path.yaml`, `gaps.yaml`, `scoring.yaml` (copy ACE's; constants are shared) and `README.md`. Follow the ACE pack's structure and README.
2. Take activities, module and item titles from the public Google Skills path outline; take section names, weights and objective titles from the official exam guide. Never copy descriptions, transcripts, lab instructions, quiz questions or exam-guide text beyond titles.
3. Map every exam-relevant module to objective ids and `core` or `support`; mark introductions, summaries and resources `examRelevant: false`.
4. Write gap topics and concept titles in your own words, with 1–3 official documentation URLs per gap concept. Check every URL returns 200 and use canonical (post-redirect) URLs.
5. Generate and test the seed: edit the pack YAML, run `python3 scripts/build-plugin-data.py`, and check the counts it prints. The ready batches land in `skills/init/assets/packs/<certId>/seed/` (commit them).
6. Mention the pack in the init skill's certification step and in the README.

## Evals

Behavior tests live in `evals/` and are generated by `scripts/gen-evals.py` from one invented tracker fixture; see [evals/README.md](evals/README.md).

```bash
claude auth login                                    # once
python3 scripts/gen-evals.py                         # after editing cases
scripts/run-evals.sh --model sonnet --runs 1 -j 4    # with and without the plugin
```

A change to a skill should keep every case passing and must not lower the delta over the no-plugin baseline. Add a case for every new behavior or fixed bug. Summarize notable runs in `evals/RESULTS.md`. Never commit `evals/results/` or transcripts of your own sessions.

## Checks

```bash
claude plugin validate ./plugins/gcp-cert-coach --strict
claude plugin validate . --strict
scripts/check-privacy.sh
scripts/check-consistency.sh
```

The pre-commit hook runs the privacy check and gitleaks on staged files; the pre-push hook adds the full tracked-file scan and plugin validation; CI runs everything on every push and pull request.

## Privacy rules

- No personal data anywhere: no real names, emails, usernames (except the owner's public GitHub handle in manifests, license and repository URLs), claude.ai artifact URLs, Google Cloud project ids, billing ids or screenshots of real accounts.
- Example data is invented and labeled as example.
- Never commit transcripts or outputs of manual tests on your own account; summarize results in neutral terms.
- A false positive gets a narrowly scoped, commented rule in `scripts/privacy-allowlist.txt`.

## Writing skills

Follow the rules in [CLAUDE.md](CLAUDE.md) → Skill authoring: third-person descriptions with trigger terms and "not for" guidance, bodies under 500 lines, references one level deep, consistent terminology (activity, module, concept, level, coverage, readiness, misconception, tracker, pack), no surface-specific tool names, no time-sensitive phrasing.

## Releases

1. Update `CHANGELOG.md`.
2. Bump the version in `plugin.json`, `.claude-plugin/marketplace.json`, `PLUGIN_VERSION` in `templates/tracker.html`, then run `scripts/build-plugin-data.py` so the template JSON and the seed carry it (`scripts/check-consistency.sh` verifies they match).
3. Run validate, evals and the checks above; commit; tag `v<version>`.

## Commits

Conventional commits in English (`feat:`, `fix:`, `docs:`, `chore:`, `test:`), no personal data in messages.
